프로젝트가 해결하는 문제

일반 CMS는 수식을 이미지처럼 다루거나 선택지 순서와 정답을 단순 번호로 저장합니다. 이 프로젝트는 수학 콘텐츠에서 실제로 문제가 되는 표현 품질, 재편집 가능성, 정답 정합성, 동시 편집을 데이터 설계 단계에서 해결합니다.

01

수학 표현을 구조로 보존

본문은 JSON 문서, 수식은 원본 LaTeX와 정규형, 작도는 편집 가능한 JSON과 표시용 SVG로 나눠 저장합니다.

02

저장본을 덮어쓰지 않음

정식 저장마다 불변 버전을 추가합니다. 과거 문항과 정답을 언제든 다시 확인할 수 있습니다.

03

편집 충돌을 숨기지 않음

기준 버전과 초안 revision을 함께 검사하여 다른 탭의 변경을 조용히 덮어쓰지 않습니다.

핵심 설계 의도

기술 선택의 기준은 “빠르게 입력하되, 나중에 다시 편집할 수 있고, 저장된 문항의 의미가 바뀌지 않아야 한다”입니다.

입력과 표시의 분리
MathLive는 입력 경험을, MathJax 4는 최종 표시를 담당합니다. 입력 위젯의 표현 방식이 바뀌어도 저장·내보내기의 결과를 한 엔진으로 통일하기 위한 선택입니다.
원본과 파생물의 분리
LaTeX 저자 원본과 정규형, 작도 JSON과 SVG, 문항 JSON과 검색 문자열을 함께 두되 역할을 구분합니다. 원본은 보존하고 파생물은 다시 만들 수 있게 설계했습니다.
DB가 마지막 방어선
애플리케이션 검증만 믿지 않습니다. 정답-선택지 복합 외래키, 현재 버전 관계, 불변 트리거, 버전 완전성 검사를 PostgreSQL에도 둡니다.
큰 작업의 비동기화
내보내기와 백업은 요청 응답에서 분리된 Worker가 처리합니다. 사용자는 작업 상태를 확인하고 완료된 결과만 다운로드합니다.
배포 환경 교체 가능성
개발에서는 로컬 파일 시스템과 임베디드 PostgreSQL을 사용합니다. 운영에서는 같은 인터페이스를 통해 S3와 외부 PostgreSQL로 바꿀 수 있습니다.

LaTeX와 Math 라이브러리는 어떻게 쓰이는가

LaTeX는 라이브러리가 아니라 수식을 표현하는 문자열 문법입니다. 이 프로젝트는 LaTeX 원문을 중심 데이터로 삼고, 입력·검증·표시를 서로 다른 도구에 맡깁니다. 각 도구의 책임을 섞지 않는 것이 핵심입니다.

01 · INPUTMathLive

수식 전용 입력 필드와 기호 팔레트를 제공합니다. 사용자의 키 입력을 LaTeX 문자열로 만듭니다.

02 · VALIDATE@mathcms/math

자체 파서가 허용 명령, 그룹, 인자, 첨자, 행렬 크기와 중첩 한도를 검사합니다.

03 · NORMALIZECanonical LaTeX

같은 의미의 표현을 정규형으로 바꾸고, 사용자가 쓴 원본은 latex_authored에 보존합니다.

04 · TYPESETMathJax 4 + NewCM

격리된 서버 Worker에서 SVG와 MathML을 만들고 읽기용 문자열도 함께 준비합니다.

05 · OUTPUTRenderer + Cache

미리보기, 상세 화면, 오프라인 HTML이 같은 결과를 사용하고 DB 캐시로 재사용합니다.

기술 / 모듈이 프로젝트에서의 역할의도적으로 맡기지 않은 역할
LaTeX분수, 첨자, 행렬 같은 수학 의미를 텍스트로 보존하는 원본 형식입니다. 에디터와 DB, export 사이의 공통 언어입니다.그 자체로 화면을 그리거나 안전성을 검증하지 않습니다. 문자열만 저장해도 올바른 수식이 되는 것은 아닙니다.
MathLive 0.110브라우저의 math-field, 가상 키보드, 커서 이동, 빈칸 이동 등 저작 경험을 담당합니다. 팔레트 선택도 MathLive 명령으로 삽입됩니다.최종 저장 형식이나 최종 렌더링 엔진으로 사용하지 않습니다. MathLive가 생성한 문자열도 자체 검증을 통과해야 합니다.
@mathcms/math프로젝트 전용 허용 목록 파서입니다. LaTeX 길이 2,000자, 중첩 20단계, 행렬 크기 등의 제한을 적용하고 canonical LaTeX와 검색·접근성용 읽기 문자열을 만듭니다.TeX 전체 문법을 구현하지 않습니다. 교육과정에 필요한 검증된 하위 집합만 지원하여 예측 가능성과 안전성을 높입니다.
MathJax 4.1검증된 LaTeX를 NewCM 수학 글꼴로 조판하여 SVG와 MathML로 변환합니다. 브라우저 미리보기와 저장본·export가 같은 엔진을 사용합니다.사용자 입력 UI와 문법 정책을 결정하지 않습니다. 유효성의 기준은 앞 단계의 자체 파서입니다.
Node WorkerMathJax를 앱 요청 처리 흐름에서 분리합니다. 작업당 2초, old generation 128MB 제한을 두고 실패한 Worker를 교체합니다.수식 원본을 소유하지 않습니다. Worker가 실패해도 원문은 버전에 남습니다.
RenderCachecanonical LaTeX, inline/display 모드, 표시 폭, 엔진 버전에 대응하는 SVG·MathML·speech를 저장합니다.콘텐츠 정본이 아닙니다. 엔진 프로파일이 바뀌면 새 키로 다시 만들 수 있는 파생 데이터입니다.
Tiptap본문 JSON 안에서 mathInline과 mathBlock 노드를 배치하고, 일반 텍스트·표·이미지와 함께 편집합니다.수식 내부 편집과 조판은 각각 MathLive와 MathJax에 위임합니다.

검증·정규화 후 · latex\frac{1}{2}+x^{2}
INLINE / DISPLAY

두 가지 수식 노드

mathInline은 문장 안에서 글과 함께 흐르고, mathBlock은 독립된 줄에 표시됩니다. 편집 화면에서 두 모드를 서로 전환할 수 있습니다.

단일 표시 경로

같은 수식은 같은 결과로

편집 미리보기, 문항 상세, 공통 Renderer, 오프라인 export가 동일한 MathJax 캐시를 사용합니다. 화면마다 수식 모양이 달라지는 문제를 줄입니다.

오류 처리

오류도 데이터 손실 없이

지원하지 않는 명령이나 비어 있는 인자는 저장 전에 위치와 이유를 알려줍니다. 조판 단계가 실패한 경우에도 authored/canonical 원문은 지우지 않습니다.

접근성과 검색

SVG만 저장하지 않는 이유

MathML은 보조 기술을 위한 구조를, 읽기 문자열은 검색과 대체 표현을 제공합니다. SVG는 시각 결과이며 세 가지를 함께 생성합니다.

핵심 기능은 어떻게 동작하는가

아래 탭을 선택하면 각 기능의 사용자 경험과 서버 내부 동작을 함께 볼 수 있습니다.

충돌 방지

두 탭에서 동시에 편집하면

서버가 문항 행을 잠근 뒤 base version과 draft rev를 비교합니다. 하나라도 다르면 409를 반환하고 기존 내용을 덮어쓰지 않습니다.

데이터 설계의 중심

Question은 문항의 정체성과 현재 상태를 가리키는 얇은 포인터입니다. 실제 콘텐츠는 QuestionVersion 아래에 고정됩니다. 이 구조가 이력, 복사, 정답 보존, 안전한 내보내기를 가능하게 합니다.

Core principle현재 상태는 움직이지만
저장된 버전은 움직이지 않는다.

Question.currentVersionId만 새 버전을 가리키도록 바꾸고, 이전 QuestionVersion·Choice·Answer·VersionAsset은 수정하지 않습니다.

정답은 같은 버전의 Choice uid만 참조
현재 버전은 같은 Question에 속한 버전만 허용

문항 콘텐츠는 HTML이 아니라 구조다

에디터 화면은 HTML처럼 보이지만 저장 형식은 버전이 명시된 JSON 트리입니다. 표시 환경이나 에디터가 바뀌어도 데이터 의미를 해석할 수 있습니다.

{
  "body": { "type": "doc", "schema_version": 1, … },
  "choices": [
    { "uid": "선택지 UUID", "content": { … } }
  ],
  "answer_uid": "선택지 UUID",
  "category_id": "소분류 UUID",
  "difficulty": "medium",
  "tag_ids": ["태그 UUID"]
}

허용 노드

paragraph, text, hardBreak, mathInline, mathBlock, image, figure, bogi, table, tableRow, tableCell, tableHeader

주요 제한

문서 깊이 10, 노드 3,000개, 문항당 수식 200개, 선택지 2~5개, 태그 30개. 수식·자산 노드는 필수 속성을 검증합니다.

스키마 버전

schema_version: 1을 문서 자체에 저장해 향후 변환 경로를 만들 수 있게 했습니다.

정합성과 보안 장치

한 번의 검사에 의존하지 않고 브라우저, API, 서비스, DB, 파일 저장소에서 서로 다른 실패를 막습니다.

1
입력 검증

Zod가 API 입력과 문서 JSON을 허용 목록 방식으로 검사합니다.

2
Workspace 격리

모든 서비스 쿼리와 복합 관계에서 로그인 사용자의 영역을 제한합니다.

3
트랜잭션·행 잠금

버전 저장과 일괄 작업은 관계 데이터 전체가 성공할 때만 반영됩니다.

4
DB 제약·트리거

정답 참조, 버전 완전성, 불변 데이터 규칙을 우회하기 어렵게 합니다.

5
세션 보안

Argon2 비밀번호, opaque 세션, HttpOnly·SameSite 쿠키, 로그인 잠금을 사용합니다.

6
요청 경계

변경 Origin 검사, 크기 제한, 파일 magic type 검사, 인증 다운로드를 적용합니다.

7
조판 격리

MathJax를 제한된 Node Worker에서 실행하고 시간 초과 시 재생성합니다.

8
복구 가능성

백업은 DB 스냅샷과 파일을 묶고, 복원 시 건수와 참조를 대조합니다.

하나의 저장소에서 화면, 서버 서비스, 재사용 도메인 엔진, 운영 스크립트를 분리했습니다.

운영 데이터의 흐름

PostgreSQL은 관계와 상태의 기준이며, 파일 저장소는 원본 자산과 생성 결과를 보관합니다. 둘을 함께 백업해야 복원 가능한 시스템이 됩니다.

LOCAL

개발 환경

Embedded PostgreSQL 16과 로컬 파일 디렉터리를 사용합니다. 샘플은 SEED_DEMO=true일 때만 만듭니다.

PRODUCTION PATH

운영 전환 구조

외부 PostgreSQL과 비공개 S3로 전환할 수 있습니다. 웹과 Worker가 동일 DB·저장소 설정을 공유합니다.

RECOVERY

백업과 복원

PostgreSQL 16 스냅샷과 파일을 ZIP으로 묶고, 다른 빈 DB와 별도 파일 경로에만 복원합니다.
